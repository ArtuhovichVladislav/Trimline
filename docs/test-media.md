# Test media set

A set of real-world and generated files for checking Trimline by hand before a release (see
[`spec.md`](spec.md#testing)). It lives outside the repository and is built by a script:

```sh
scripts/make-test-media.sh              # into ~/Projects/Trimline-TestMedia, about 700 MB, 5–10 minutes
scripts/make-test-media.sh --big        # plus a 20 GB MOV and a 50 GB MKV
scripts/make-test-media.sh ~/Media/Set  # into another folder
```

The script needs a Homebrew `ffmpeg` with libx264, libx265, libvpx, libsvtav1, libopus and libmp3lame. A rerun
only downloads and generates what is missing. Downloaded samples are cached in `$TMPDIR/trimline-media-cache`.

Real files come from the [MPlayer samples archive](https://samples.mplayerhq.hu),
[hdr-tests](https://github.com/haasn/hdr-tests) and [Dolby's Dolby Vision samples](https://github.com/DolbyLaboratories/dolby-vision-contents).
Everything else is generated by ffmpeg: a moving test pattern and a tone with smoothly changing volume, so the
waveform is visible.

## Folders

| Folder | Contents | What to check |
| --- | --- | --- |
| `01-phones` | Dolby Vision 8.4 (iPhone profile) and 5, HEVC HLG 10-bit, vertical video with rotation, H.264 with variable frame rate (Android), 3GP with H.263, M4V, ProRes | Opens through AVFoundation, HDR doesn't look washed out, rotation is applied in the preview and in the clip |
| `02-messengers` | Telegram and WhatsApp videos, video messages and voice messages (MP4, OGG Opus, `.opus`) | Voice messages open through FFmpeg and are saved in the same container |
| `03-large` | 2880×1800 screen recording, 4K and 8K HEVC, a 3-hour video, 2- and 10-hour MP3s; with `--big`, a 20 GB MOV and a 50 GB MKV | Opens in ≤ 1 s, 8K thumbnails in ≤ 2 s, waveform of the 2-hour MP3 in ≤ 5 s, memory ≤ 150 MB |
| `04-legacy` | AVI (DivX 3 and 5, Xvid, MJPEG), WMV 7/8/9 and VC-1, FLV (Sorenson, H.264), F4V, MPG (MPEG-1 and 2), VOB (real and generated), OGV Theora, DV | FFmpeg opens everything, the clip is saved in the same container |
| `05-cameras` | The start of a real AVCHD recording from a Canon HG10 (1080i), M2TS, MTS, TS with MPEG-2 | Interlaced video, 192-byte packets |
| `06-audio` | MP3 and M4A with cover art, ALAC, AAC 5.1, WAV 16/44 and 24/96, AIFF, CAF, FLAC 24/192 and 5.1, AC-3, DTS, Vorbis, Opus, WMA and WMA Lossless, WavPack, AMR | Cover art doesn't disturb the waveform, multichannel audio is saved losslessly |
| `07-tracks` | Two audio tracks, two subtitle tracks and chapters in MKV, MP4 and MOV; rotation by 90, 180 and 270°; video without sound; a subtitles-only file | Stream count and types in the clip match the original; a file without playable streams shows a clear reason |
| `08-web` | WebM (VP8, VP9, AV1), AV1 in MP4, MKV with H.264, HEVC and VP9, real HDR10, HLG and Dolby Vision in MKV | AV1 on M1/M2 is decoded by dav1d |
| `09-read-only` | RM, RMVB (RealVideo 4 + Cook 5.1), APE | A notice, the clip is saved as MKV or MKA |
| `10-damaged` | MP4 without an index, MP4 whose index points past the end of the file, truncated MKV and MP3, MKV without a seek table, garbage in the middle of an MP4, wrong extension, no extension, text named as MP4, empty file | A clear reason or working with a notice, no hangs or crashes |
| `11-file-system` | Cyrillic, emoji and dashes in the name, many dots in the name, a symbolic link, a read-only folder, a locked file | Clip name, saving when the original's folder isn't writable |

## Not in the set

- External HDD and SMB network drive: copy the `03-large` and `10-damaged` folders there by hand.
- Real iPhone and Android recordings with device metadata. The Dolby Vision 8.4 file matches the iPhone profile
  but is an MP4: ffmpeg can't write it to MOV with Dolby Vision metadata. For a full check, add your own recordings
  to `01-phones`.

## Removing the set

The read-only folder and the locked file can't be deleted the usual way:

```sh
chflags -R nouchg ~/Projects/Trimline-TestMedia && chmod -R u+w ~/Projects/Trimline-TestMedia
rm -rf ~/Projects/Trimline-TestMedia
```
